Компиляция и интерпретация

C++

  • Компилятор читает весь код заранее
  • На выходе — бинарник, он самодостаточен
  • Опечатка и несовпадение типов ловятся до запуска

Python

  • Интерпретатор выполняет код по ходу дела
  • Бинарника нет: нужен сам Python на машине
  • Ошибка в редкой ветке дождётся, пока в неё зайдут
Компилятор вас больше не страхует. Страхуют тесты и линтер — поэтому они в проекте с первого дня.

Библиотеки: не линковка, а установка

  • Чужой код не собирается вместе с вашим — он ставится рядом командой pip install И подключается при запуске по имени: import aiogram
  • Список нужного проекту лежит текстом в requirements.txt Это и есть «сборочный рецепт» проекта: имя библиотеки плюс версия
  • Версия интерпретатора тоже часть требований — здесь Python 3.12 Код под 3.12 может не запуститься на 3.9: синтаксис и библиотеки разные
Отсюда классическая беда: два проекта на одной машине хотят разные версии одной библиотеки.

Виртуальное окружение: свой ящик на проект

Без venv

  • Все библиотеки валятся в общую системную папку
  • Новый проект ломает предыдущий сменой версии

С venv

  • Папка .venv внутри проекта: свой Python и свои библиотеки
  • Проекты не пересекаются, снести и пересоздать — минута
.venv в репозиторий не коммитят: он собирается из requirements.txt на любой машине.
Python4 / 13

Как запускается любой проект на Python

  • 1. Создать окружение: python -m venv .venv
  • 2. Активировать его — после этого python и pip означают «из этого проекта» macOS и Linux: source .venv/bin/activate · Windows: .venv\Scripts\activate
  • 3. Поставить зависимости: pip install -r requirements.txt
  • 4. Запустить точку входа, которая указана в README проекта README молчит — смотрят pyproject.toml, Makefile, Dockerfile либо ищут файл с if __name__ == "__main__":
Обязательной функции main, как в C++, здесь нет: запускается тот файл, который вы передали интерпретатору.

Что такое языковая модель

  • Модель получает текст и достраивает продолжение, выбирая слова по вероятности Она не ищет ответ в базе — она его сочиняет, опираясь на то, чему научилась
  • Отсюда два свойства, с которыми придётся жить: уверенно сказанная неправда · разные ответы на один и тот же запрос
  • Для вашей программы это внешний сервис по сети Таймаут, ошибка авторизации, лимит запросов, оборванный ответ — обычные события, а не исключения
Ответ модели не является доказательством правоты. Доказательство — работающая программа и тест.

Запрос — это не строка, а список ролей

system
Ты помогаешь студенту разобраться в программировании. Отвечай по-русски, коротко, с примером.
user
Чем список отличается от кортежа?
assistant
Список можно менять, кортеж — нет…
user
А какой быстрее?
system — правила приложения, задаёте вы. user — то, что написал человек. assistant — прошлые ответы модели. Роли путать нельзя: иначе модель увидит искажённый диалог.

Модель ничего не помнит

  • Каждый вызов независим: вчерашней переписки для модели не существует «Память» бота — это прошлые сообщения, которые вы сами приложили к новому запросу
  • Значит, историю хранит ваше приложение — в базе, отдельно по каждому пользователю Перезапустили бота — история на месте: она в PostgreSQL, а не в памяти процесса
  • Приложить всё не выйдет: объём запроса ограничен Контекст считается в токенах — кусочках слов; историю приходится обрезать, сохраняя порядок и роли
Два пользователя — две независимые истории. Перепутать их — не косметический баг, а утечка чужой переписки.

Системная инструкция

Что в неё кладут: R.C.T.F.

  • Role — роль: кем работает ассистент
  • Context — контекст: что известно о ситуации
  • Task — задача: что именно сделать
  • Format — формат: язык, объём, структура ответа

Чего не кладут

  • Ключи, пароли, токены
  • Правила «кому что можно»

Инструкция направляет модель, но не защищает: пользователь может попросить её нарушить.

Ограничения проверяет код приложения. Всегда, независимо от того, что ответила модель.

Диалоговое приложение

  • Текст вошёл — текст вышел
  • Внешнего мира не существует: ни погоды, ни вашей базы, ни отправки письма

Это лабораторная № 1

Агент

  • Модель выбирает действие из разрешённого списка
  • Действие выполняет ваш код и возвращает результат
  • С этим результатом модель формулирует ответ
